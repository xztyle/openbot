### Security

- The server control socket now asks the kernel which process connected. Agents run as the same user as OpenBot, so before, a prompt-injected agent could call it to make a Mobile Connect code, sign the server out or in to another account, write a database snapshot anywhere, message other agents as the owner, or move agents between spaces. Now only `status` and `health` answer a process of an agent; everything else answers only an operator who runs it through `docker exec` or from a login shell on the server. Operators need no token, and `openbot` explains the new `operator_only` refusal.
- A Claude agent's MCP servers, with the tokens in their headers and env, no longer go on the Claude command line, where every process of the user could read them in `/proc`. They go in a file that only the user can read, which OpenBot removes as soon as Claude has read it.
- On a server, agent processes no longer inherit the whole environment of the service or the container. They get the system basics, the locale, proxies and certificates, git, and the variables that the provider CLIs read; other variables, such as an operator's own keys, stay with OpenBot.
- The signing secret of the Motion events route comes only from `OPENBOT_MOTION_EVENTS_SECRET` in the host environment, which OpenBot takes out of the environment before agents start. A `MOTION_EVENTS_SECRET` in the shared Secrets is no longer used: every agent can read the shared Secrets, so an agent could sign an event that wakes any agent. Move it to the environment.
- When a Claude Code session starts OpenBot, its session variables no longer reach the agents.
- The web app and the iPhone app pin the first key that they see for a joined server. A later key change is accepted only with a handover that both keys signed; without one, only the connection to that server fails, not the server list. Before, they used any key that the account service listed for a server with no pin. (Upstream 21d080a49.)
- A tab that a member opens in an agent's browser panel on a joined server opens in that agent's browser profile again, not in the shared profile, where its sign-in reached every agent. (Upstream 2357441bb.)
- A member's Storage view lists the chats and files only of the agents that they can see. Before, it also listed the chats and files of agents that their role closes to them, and a file id was enough to download the file. (Upstream ceb099ce3.)
- A member no longer lists or opens a channel whose members are all agents that their role closes to them, and a channel page or thread leaves out the messages of such agents. Owners and admins keep every channel. (Upstream 31b1a0396, also applied to the workspace thread and command routes.)
- Logs redact the token after any `Authorization` scheme (Discord sends `Bot <token>`), the value of an environment pair such as `{ name: "OPENAI_API_KEY", value: … }`, Google OAuth tokens and client secrets, Telegram bot tokens, and Slack and Discord webhook addresses. (Upstream ad4e6920e.)
- The address guard of MCP sign-in and other fetches refuses the rest of `::/64` (IPv4-compatible and SIIT addresses), and classifies NAT64 and 6to4 addresses as the IPv4 address that they reach. Signal compares its metrics token in constant time, and its TURN server refuses all of `::/64` as a peer. (Upstream ad4e6920e.)
- Each joined server gets its own remote viewer path secret, and the viewer proxy reaches only the remote-screen routes. Before, all joined servers shared one secret, so one host's viewer page could call another joined server with your session. (Upstream ad4e6920e.)
